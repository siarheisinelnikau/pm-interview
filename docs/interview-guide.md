# Interview and preparation guide

[Back to questions](../README.md)

## Selecting questions

The main track is **Project Manager**. Start with the core sections, add the relevant domain, and use adjacent sections only when the role actually includes those responsibilities. Titles differ between companies; establish authority and scope before evaluating a candidate against a title.

- **Junior:** explain fundamentals, keep useful records, recognize a problem, and identify when to involve an owner.
- **Middle:** make and explain delivery decisions, manage realistic uncertainty, and coordinate stakeholders independently.
- **Senior:** handle cross-team and commercial consequences, challenge weak assumptions, and create a decision path when authority is unclear.

A label indicates the main depth of the question, not a rigid hiring threshold.

## A 60-minute interview

| Time | Focus | Suggested selection |
| --- | --- | --- |
| 0–5 min | Role and context | Clarify project scale, mandate, and domain |
| 5–15 min | Delivery fundamentals | Success, estimates versus commitments, acceptance |
| 15–30 min | Practical decision | At-risk launch, client dependency, or scope change |
| 30–40 min | Relevant domain | Two questions from Healthcare, Fintech, or Cybersecurity |
| 40–50 min | Leadership and evidence | A real failure and a stakeholder conflict |
| 50–55 min | Adjacent remit | Product, Delivery, or Presales if relevant |
| 55–60 min | Candidate questions | Leave space for the candidate to investigate the role |

For a Junior interview, spend more time on clear examples and basic ownership. For Senior candidates, probe assumptions, alternatives, authority, and the outcome after their decision.

## Evaluating an answer

Listen for a connected explanation: **context → evidence → options → decision owner → action → verification**.

| Dimension | Evidence to listen for |
| --- | --- |
| Problem framing | Clarifies objective, users, constraints, and missing information |
| Judgment | Weighs plausible options and acknowledges uncertainty |
| Ownership | Separates their own responsibility from specialist and sponsor authority |
| Execution | Names concrete next actions, dependencies, and escalation timing |
| Learning | Checks the result and can explain what changed afterward |

Use a simple 0–3 score for each dimension: 0 = no usable evidence; 1 = mostly terminology; 2 = workable approach with some gaps; 3 = well-supported reasoning and follow-through. Record evidence, then calibrate against the actual role. Do not use the total as an automatic hiring decision.

Follow-ups reveal depth: “What evidence did you use?”, “Who could accept that risk?”, “What did you stop doing?”, “How did you know the action helped?”

## Practice cases

Use a case without opening its answer first. Spend two minutes clarifying the objective and missing facts, five minutes comparing options, and three minutes presenting a recommendation.

| Case | Starting prompt | Useful artifact |
| --- | --- | --- |
| Schedule recovery | [Launch date at risk](../answers/planning-and-estimation/recovery-plan.md) | Options, forecast, decision deadline |
| Scope | [A hospital adds a site](../answers/scope-and-requirements/change-control.md) | Change request |
| Healthcare | [Unresolved patient matching](../answers/healthcare/healthcare-launch-case.md) | Readiness evidence and clinical escalation |
| Fintech | [Uncertain payment after timeout](../answers/fintech/provider-outage-case.md) | Incident coordination and reconciliation ownership |
| Cybersecurity | [Hundreds of vulnerability findings](../answers/cybersecurity/vulnerability-prioritization.md) | Prioritized treatment and verification plan |
| Presales | [Sales-to-delivery handover](../answers/presales-adjacent/sales-to-delivery-handover.md) | Assumptions, commitments, and unresolved decisions |

Discuss how the answer changes for a different jurisdiction, business model, contract, or level of authority.

## A focused seven-session preparation plan

1. **Foundations and planning:** explain success, role boundaries, estimation, capacity, and critical path using one familiar project.
2. **Scope and flow:** write acceptance examples, handle a change request, and explain Scrum and Kanban responsibilities.
3. **Risk and commercials:** build a small RAID log, prepare a budget forecast, and interpret the EVM example.
4. **People and communication:** write a concise status report and prepare two true behavioral stories using STAR.
5. **Technology and release:** walk through an integration, migration, go/no-go, recovery, and operational handover.
6. **Domain and adjacent responsibilities:** study the relevant domain and the adjacent remit mentioned in the vacancy.
7. **Mock interview:** run the 60-minute format, identify weak evidence, and revise answers using real experience.

Use the [templates](../templates/README.md) for practice. Do not memorize invented project outcomes or present illustrative metrics as personal experience.
