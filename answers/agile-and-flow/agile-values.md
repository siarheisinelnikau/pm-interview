# What does Agile mean in practice, and what does it require from a PM?

[Back to questions](../../README.md#agile-scrum-and-kanban)

**Level:** Junior · **Topic:** Agile, Scrum, and Kanban · **Reviewed:** 2026-10-30

## Answer

Agile emphasizes short feedback cycles, useful increments, collaboration, and adaptation. A PM can support this by clarifying constraints, enabling stakeholder access, making dependencies visible, and using evidence to revise plans.

In a claims project, demonstrate and test one working path early enough to discover incorrect workflow assumptions. Maintain the funding and risk information needed for decisions while avoiding documents that nobody uses. Explain how feedback changes scope and forecasts. Iteration is ineffective if every review is ceremonial and every learning opportunity is rejected because the initial plan must remain untouched.

## Show adaptation in a delivery decision

Suppose a claims review shows that users still copy information into a second system. The team has delivered the requested screen, but the intended benefit is absent. Investigate the workflow, revise the next increment, and update the forecast if integration is necessary.

A PM helps arrange the feedback, explain the trade-off to the sponsor, and remove external impediments. The product decision maker decides priority; the team supplies implementation evidence.

Agile's preference for working software over excessive documentation does not imply that documentation has no value. Retain records that support decisions, operation, traceability, or an applicable obligation. Judge the process by useful feedback and results rather than the number of short meetings.
